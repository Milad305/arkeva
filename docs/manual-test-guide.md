## ۰. پیش از شروع

### ۰.۱ راه‌اندازی

پایگاه دادهٔ PostgreSQL محلی باید بالا باشد و migration و دادهٔ نمونه یک بار اجرا شده باشد:

```bash
pnpm --filter @projeyar/backend run build
```

```bash
pnpm --filter @projeyar/backend run db:migrate
```

```bash
pnpm --filter @projeyar/backend run db:seed
```

سپس دو سرور را از `.claude/launch.json` بالا بیاورید: `projeyar-api` (درگاه ۳۰۰۰؛ `start` همان `dist/main.js` است، پس پس از هر
تغییر کد بک‌اند دوباره build لازم است) و `projeyar-web` (درگاه ۵۱۷۳). نشانی پنل: `http://localhost:5173`.

- `APP_ROLE=all` در `.env.development`: همان فرایند API، صف کارها (pg-boss) و تیک‌های زمان‌دار را اجرا می‌کند. اگر فقط `api`
  بالا باشد، محاسبه، هشدار، اعلان و پشتیبان هرگز اجرا نمی‌شوند و همهٔ اعداد صفر می‌مانند.
- `SMS_PROVIDER=console`: پیامک‌ها (کد ورود، هشدار قفل، دعوت) فقط در لاگ سرور API چاپ می‌شوند. ارائه‌دهندهٔ ایمیل هم console است.
- کد یک‌بارمصرف توسعه همیشه **۱۲۳۴۵۶** است (هر رقم در یک خانه).

### ۰.۲ این آزمون پایگاه دادهٔ توسعهٔ شما را تغییر می‌دهد

- **پیش از شروع** از پایگاه داده نسخهٔ پشتیبان بگیرید (مثلاً `pg_dump` با همان نشانی مدیر که در `.env.development` دارید؛ این
  راهنما رازها را نمی‌خواند و چاپ نمی‌کند). `db:seed` تکرارپذیر است ولی چیزی را **برنمی‌گرداند**: ردیف‌هایی که می‌سازید می‌مانند.
- واقعیت‌ها (آیتم تأییدشده، ردیف هزینهٔ قطعی، دورهٔ بسته، ممیزی) عمداً حذف‌شدنی نیستند. اگر داستان را دوباره اجرا کنید،
  یک پروژهٔ تازه با کد تازه بسازید.
- ستون «داده می‌سازد؟» در جدول ۳ می‌گوید هر سناریو چه چیزی می‌نویسد.

### ۰.۵ ابزار کنسول `pj` (فقط برای دفتر هزینه و عددهای تاریخ گذشته)

پنل را در **مرورگر خودتان** (Chrome یا Edge، نه پنجرهٔ داخلی) باز کنید، با کاربر مورد نظر وارد شوید، F12 بزنید و در زبانهٔ
Console این را بچسبانید. ابزار با همان کوکی نشست شما یک توکن تازه می‌گیرد؛ کاربر عوض نمی‌شود.

```js
// پروژه‌یار — ابزار آزمون دستی؛ فقط محیط توسعه
window.pj = async (method, path, body) => {
  if (!window.__pjToken || Date.now() > window.__pjExp) {
    const r = await fetch('/v1/auth/refresh', { method: 'POST', headers: { 'X-Requested-With': 'projeyar' } });
    const j = await r.json();
    if (!r.ok) { console.error('ورود لازم است', j); throw j; }
    window.__pjToken = j.data.accessToken;
    window.__pjExp = Date.now() + (j.data.expiresInSec - 30) * 1000;
  }
  const r = await fetch('/v1' + path, {
    method,
    headers: { Authorization: 'Bearer ' + window.__pjToken, 'Content-Type': 'application/json', 'X-Requested-With': 'projeyar' },
    body: body ? JSON.stringify(body) : undefined,
  });
  const j = r.status === 204 ? null : await r.json();
  console.log(method, path, r.status, j);
  return j;
};
// شناسهٔ یک کد (C1، 1.2.1، …) را در هر عمق پاسخ پیدا می‌کند
window.pjFind = (o, code) => {
  if (!o || typeof o !== 'object') return null;
  if (o.code === code && o.id) return o.id;
  for (const v of Object.values(o)) { const r = pjFind(v, code); if (r) return r; }
  return null;
};
```

شناسهٔ پروژه را از نشانی صفحه بردارید (`/projects/<شناسه>`) و در `P` بگذارید: `const P = '...';`

### ۰.۷ نمایش اعداد

- ارقام فارسی، جداکنندهٔ هزارگان `٬` و ممیز `٫`؛ علامت منفی `−`. کدها (WBS، CBS، `FR-…`، `RSK-…`) لاتین و تک‌فاصله.
- مبلغ‌ها با واحد خودکار: ≥ یک میلیارد ← «میلیارد ریال» با یک رقم اعشار؛ ≥ یک میلیون ← «میلیون ریال». پس ۱٬۰۰۰٬۰۰۰٬۰۰۰
  ریال «۱ میلیارد ریال»، ۵۲۰٬۰۰۰٬۰۰۰ «۵۲۰ میلیون ریال» و ۱٬۰۶۱٬۲۲۴٬۴۹۰ «۱٫۱ میلیارد ریال» دیده می‌شود.
- CPI و SPI با دو رقم اعشار (۰٫۹۴). دیالوگ «از کجا آمد؟» تا چهار رقم.
- طبقه‌بندی همیشه با عدد گردنشده است.

## ۱. واژه‌نامه

| واژه | در دنیای واقعی | در پروژه‌یار | خوب / بد |
|---|---|---|---|
| **پروژه** | یک قرارداد ساخت، مثل یک ساختمان | واحد اصلی؛ وضعیت‌ها: پیش‌نویس، فعال، متوقف، تمام‌شده، بایگانی | — |
| **WBS** (ساختار شکست کار) | فهرست درختی همهٔ کارهایی که باید انجام شود | درخت آیتم‌ها با کد `1.1`، `1.2.1`؛ **برگ** (کوچک‌ترین کار) گزارش و بودجه می‌گیرد، **والد** فقط گروه است | — |
| **وزن** | اهمیت هر کار در پیشرفت والدش | جمع وزن فرزندان هر والد باید **دقیقاً ۱۰۰** باشد؛ وزن در پروژه = حاصل‌ضرب وزن‌ها در مسیر | جمع ≠ ۱۰۰ خطای مانع است |
| **روش اندازه‌گیری** | چطور می‌گوییم کار چقدر جلو رفته | مقداری (۱۸۰ از ۲۰۰ مترمکعب = ۹۰٪)، درصدی (سرپرست درصد می‌گوید)، گام‌های وزنی (قالب ۲۰ + آرماتور ۲۰ + بتن ۶۰)، زمانی (خودکار با گذر زمان؛ گزارش نمی‌گیرد) | — |
| **نقطهٔ عطف** | رویداد بی‌مدت، مثل «تحویل موقت» | برگ با وزن معمولاً ۰؛ گزارش و اتصال CBS نمی‌گیرد | — |
| **CBS** (ساختار شکست هزینه) | فهرست اقلام هزینهٔ پیمانکار: بتن، آرماتور، دستمزد | قلم نرخ‌واحد (مقدار × نرخ) یا مقطوع (یک مبلغ)؛ با نوع هزینه | — |
| **اتصال WBS↔CBS** | این کار چقدر از کدام قلم مصرف می‌کند | زیربودجهٔ اتصال = مقدار × نرخ (یا مبلغ مقطوع)؛ **BAC برگ** = جمع زیربودجه‌ها | برگ بی اتصال بودجه و EV ندارد |
| **BAC** | کل بودجهٔ کار | جمع BAC برگ‌ها | — |
| **پیشرفت برنامه‌ای** | جایی که طبق برنامه باید باشیم | برای هر برگ خطی روی **روزهای کاری** تقویم پروژه، از شروع تا پایان برنامه‌ای | — |
| **پیشرفت فیزیکی واقعی** | جایی که واقعاً هستیم | فقط از آیتم‌های **تأییدشده**، تجمیع با وزن | — |
| **انحراف** | چقدر جلو یا عقبیم | واقعی − برنامه‌ای، به **واحد درصد**. d ≤ −۱۵ بحرانی؛ −۱۵ < d ≤ −۵ هشدار؛ −۵ < d ≤ ۰ طبق برنامه؛ d > ۰ جلوتر | دقیقاً −۵ «هشدار»، دقیقاً ۰ «طبق برنامه» |
| **پیشرفت ریالی** | چند درصد پول بودجه «کسب» شده | EV ÷ BAC؛ با وزن دستی کمی با فیزیکی فرق دارد (۴۹٫۰ در برابر ۴۹٫۲) | — |
| **PV** (ارزش برنامه‌ای) | ارزش کاری که **باید** تا امروز انجام می‌شد | Σ BAC برگ × پیشرفت برنامه‌ای برگ | — |

## ۷. اگر عددی نخواند

1. **تازه کنید و صبر کنید.** نشان «در حال به‌روزرسانی» یعنی محاسبه هنوز در صف است. اگر `compute_state` «failed» شد، لاگ API را ببینید.
