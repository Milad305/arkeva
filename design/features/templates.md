## ۱. هدف و مشکل دنیای واقعی

یک شرکت ساختمانی سال‌ها پروژهٔ شبیه به هم می‌سازد: ساختمان بتنی ۸ تا ۱۵ طبقه همیشه همان فصل‌ها دارد (عملیات خاکی، فونداسیون، اسکلت، …) با وزن‌های تقریباً یکسان. هر بار ساختن ۸۶ آیتم WBS و ۴۲ قلم CBS از صفر، هم وقت‌گیر است و هم هر پروژه با ساختاری متفاوت ساخته می‌شود و مقایسه‌شان سخت است. **قالب** تجربهٔ شرکت را ذخیره می‌کند تا پروژهٔ تازه در چند دقیقه ساخته شود.

## ۲. مفاهیم

| **نسخهٔ قالب (`TemplateVersion`)** | محتوای تغییرناپذیر یک انتشار؛ شمارهٔ ۱، ۲، … |

| **زمان نسبی** | شروع و مدت هر آیتم به روز کاری نسبت به شروع پروژه |

## ۳. پیش‌نیازها

## ۴. داده
`Template` و `TemplateVersion` در `02-domain-model.md` بخش ۱۲ هستند. ساختار `content` (json، نسخه‌دار):

```
content {
  schemaVersion
  referenceDurationWd        // مدت مرجع قالب به روز کاری
  wbs[]  { key, parentKey, title, sortOrder, isMilestone, weightInParent,
           measurementMethod, steps[], unit?, startOffsetWd, durationWd, areaKey? }
  cbs[]  { key, parentKey, title, costType, unit?, pricingMode, sharePct? }       // sharePct فقط برگ، جمع ۱۰۰
  links[] { wbsKey, cbsKey, parts }                                              // parts عدد صحیح ≥ ۱
  areas[] { key, name, wbsRootKeys[] }                                            // بدون ناظر
  settings { weightGenerator, thresholds, reportRules, approvalMode, stage2*,
             reviewDeadlineHours, onDeadline, autoApprove*, eacMethod }
}
```
- **مقدار کل** (`totalQuantity`) و **سرپرست** و **نرخ واحد** در قالب نیستند؛ مختص پروژه‌اند. واحد (`unit`) هست.
- قلم CBS در پروژهٔ ساخته‌شده همیشه `lump_sum` است (بخش ۵.۳). کاربر بعداً می‌تواند به `unit_rate` تغییر دهد.
- نسخهٔ پروژه: `Project.templateRef { templateId, version }` فقط برای اطلاع (آمار استفاده، W31).

### ۵.۲ اعتبارسنجی (هنگام انتشار)
همان قواعد F04 به‌اضافه:
- جمع وزن هر گروه و سطح اول ۱۰۰ (D04)؛ جمع `sharePct` برگ‌های CBS ۱۰۰؛ هر قلم CBS دست‌کم یک اتصال و هر برگ WBS غیرزمانی دست‌کم یک اتصال (هشدار، نه مانع).
- روش `quantity` ممکن است در قالب باشد با واحد ولی بدون مقدار؛ در پروژه، مقدار کل الزامی است و پیش از فعال‌سازی باید پر شود (هشدار فعال‌سازی).
- کد WBS خودکار تولید می‌شود (`wbs.md` ۵.۲).
- گام‌ها طبق `wbs.md` ۴.۲.
- بدون اعتبار ← پیش‌نویس می‌ماند و منتشر نمی‌شود.

### ۵.۳ ساخت پروژه از قالب (W38)
ورودی: قالب، تاریخ شروع و پایان پروژه، بودجهٔ کل و ذخیره (ویزارد، F02).

1. **ساختار:** WBS کپی می‌شود (شناسه‌های تازه). کدها از ساختار ساخته می‌شود.
2. **تاریخ‌ها:** `ضریب = روز کاری پروژه ÷ referenceDurationWd`؛ `شروع = شروع پروژه + round(startOffsetWd × ضریب)` روز کاری و `پایان = شروع + max(1, round(durationWd × ضریب)) − 1` روز کاری؛ همه با تقویم پروژه و نقطهٔ عطف در یک روز. پایان هیچ آیتمی از پایان پروژه بیرون نمی‌زند (برش).
3. **بودجه:** `بودجهٔ CBS = بودجهٔ کل − ذخیره`. هر برگ CBS: `round(بودجهٔ CBS × sharePct ÷ 100)`؛ **باقی‌ماندهٔ گرد کردن به آخرین برگ** تا جمع دقیق شود (C02).
4. **اتصال‌ها:** برای هر قلم، مبلغ `allocatedAmount = round(بودجهٔ قلم × parts ÷ Σ parts)`؛ باقی‌ماندهٔ گرد کردن به آخرین اتصال.
5. **حوزه‌ها:** `ApprovalRoute` بدون ناظر؛ ناظر در W48/F07 تعیین می‌شود؛ تا آن زمان AL-STR-06.
6. **تنظیمات** به `ProjectSettings` کپی می‌شود (جز آنچه ویزارد خودش تعیین کرده).
7. **محتوا نسخهٔ پیش‌نویس** پروژه می‌شود (`source = template`) و چون پروژه پیش‌نویس است مستقیم اعمال می‌شود (D05).
8. بعد از ساخت، قالب و پروژه مستقل‌اند: تغییر قالب روی پروژهٔ ساخته‌شده اثری ندارد (`02` بخش ۱۲).

**مثال عددی (باقی‌ماندهٔ گرد کردن):** بودجهٔ CBS = 1,000,000,001 ریال با دو قلم ۴۰٪ و ۶۰٪ ← قلم اول `round(400,000,000.4) = 400,000,000`، قلم دوم باقی‌مانده = **600,000,001**. جمع = 1,000,000,001.

**مثال مرجع (قالب تست):** قالب با ساختار `00-overview.md` ۶.۱ و CBS:
| قلم | سهم | اتصال‌ها (ضریب) |
|---|---|---|
| C1 | 10٪ | 1.1.1 (1) |
| C2 | 40٪ | 1.1.2 (4)، 1.2.1 (1)، 1.2.2 (3) |
| C3 | 30٪ | 1.1.2 (1)، 1.2.1 (1)، 1.2.2 (1) |
| C4 | 20٪ | 1.2.1 (3)، 1.2.2 (1) |

با بودجهٔ CBS برابر 1,000 میلیون ریال: BAC برگ‌ها 100 و 300 و 300 و 300؛ جمع **1,000**؛ دقیقاً مثال `cbs.md` ۹.۱ (به‌صورت `lump_sum`). اگر ضریب C3 از ۱:۱:۱ استفاده شود، رقم‌ها صحیح و بدون باقی‌مانده است.

### ۵.۴ چرخهٔ عمر قالب
- **`draft`:** قابل ویرایش، در W38 دیده نمی‌شود.
- **منتشر:** ساخت `TemplateVersion` جدید و تغییرناپذیر. ویرایش یک قالب منتشرشده یک پیش‌نویس تازه (نسخهٔ بعد) می‌سازد؛ تا انتشار، نسخهٔ قبلی در W38 فعال است.
- **بایگانی:** قالب از W38 و W37 پنهان می‌شود؛ پروژه‌های ساخته‌شده بی‌اثر. حذف فقط برای قالبی که هرگز استفاده نشده.
- **قالب پیش‌فرض نوع:** هر نوع پروژه می‌تواند یک قالب پیش‌فرض داشته باشد که در W37 پیشنهاد می‌شود.
- **تاریخچهٔ نسخه‌ها** (W31): شمارهٔ نسخه، تاریخ، نویسنده، یادداشت تغییر؛ مقایسهٔ دو نسخه (تعداد آیتم، وزن‌های تغییریافته).

### ۵.۵ تنظیمات همراه
فقط تنظیماتی که با پروژه کپی می‌شود: روش وزن‌دهی، آستانه‌های انحراف، قواعد گزارش کارگاه، گردش‌کار (یک یا دومرحله‌ای، شرط‌ها، مهلت)، `eacMethod`. نه: تقویم، موقعیت، تیم، اعلان‌ها، تاریخ کامل بودن هزینه‌ها.

### ۵.۶ قالب‌های اولیهٔ سازمان
نسخهٔ اول با قالب آماده نمی‌آید. سازمان قالب اول خود را از یک پروژه می‌سازد یا از Excel وارد می‌کند. (یک «قالب نمونه» فقط در محیط آزمایشی با مثال مرجع.) `[تأییدشده]`
