# F19 — یکپارچه‌سازی‌های دیگر (فاز بعد)

> **نسخه:** ۱ · **تاریخ:** 1405/08/11 · **وضعیت:** مرز فاز بعد؛ در نسخهٔ اول فقط زیرساخت و کارت‌های W30 ساخته می‌شود (بخش ۹)؛ فرض‌ها در 1405/08/11 تأیید شد
> **مبنا:** D02، D12 · **صفحه:** W30 (بخش یکپارچه‌سازی)

---

## ۱. هدف و مشکل دنیای واقعی

شرکت‌های بزرگ‌تر هزینه را در ERP یا نرم‌افزار حسابداری ثبت می‌کنند و برنامه را گاهی در Primavera P6 نگه می‌دارند. تایپ دوبارهٔ هزینه در پروژه‌یار هم وقت‌گیر است و هم خطا می‌سازد. این ویژگی اتصال به آن سیستم‌ها را تعریف می‌کند، بدون اینکه هیچ منطق محاسباتی را عوض کند: **همه چیز از راه دفتر هزینه (D02) و خروجی فایل** است.

## ۲. مفاهیم
| مفهوم | توضیح |
|---|---|
| **اتصال (`IntegrationConnection`)** | پیکربندی یک سیستم بیرونی برای یک سازمان یا پروژه |
| **اجرا (`IntegrationRun`)** | یک بار همگام‌سازی با نتیجه |
| **نگاشت حساب** | تطبیق کد حساب سیستم بیرونی با یک قلم برگ CBS |
| **ردیف نانگاشته** | ردیف بیرونی که حسابش به هیچ قلم CBS وصل نیست |
| **فقط خروجی** | اتصالی که داده نمی‌گیرد و فقط فایل می‌دهد (P6) |

## ۳. پیش‌نیازها
F06 (API ثبت هزینه)، F05 (اقلام CBS)، F04 و F10 (برای خروجی)، F20 (صف، رمزنگاری پیکربندی).

## ۴. اصول (غیرقابل‌تغییر)
1. هیچ اتصالی **مستقیم در جدول** نمی‌نویسد؛ فقط از `POST /integrations/:system/cost-entries` (F06) با `source = integration` (D02).
2. هیچ محاسبه‌ای از سیستم خارجی نمی‌خواند؛ فقط ردیف‌های دفتر هزینه (D02).
3. همهٔ ورودها idempotent با کلید `(projectId, source, externalRef)`.
4. اتصال بیرونی نباید ساختار پروژه (WBS، CBS) را بی‌صدا عوض کند.
5. وابستگی سخت به سرویس اینترنتی نیست؛ نصب اختصاصی با ERP داخلی کار می‌کند (D12).

## ۵. داده
| موجودیت | نوع | فیلدها |
|---|---|---|
| `IntegrationConnection` | پایه، مالک F19 | `orgId`، `projectId?`، `system` enum(erp, accounting, p6_export, custom)، `name`، `config` (رمزنگاری‌شده: نشانی، کلیدها)، `direction` enum(inbound, outbound)، `status` enum(not_configured, connected, error, disabled)، `schedule`، `lastRunAt`، `lastError`، `dataKinds` string[] |
| `IntegrationRun` | عملیاتی | `connectionId`، `startedAt`، `finishedAt`، `status`، `fetched`، `posted`، `skipped`، `unmapped`، `error`، `cursor` |
| `AccountMapping` | پایه | `connectionId`، `externalAccountCode`، `cbsItemId`، `projectId` |
| `UnmappedRow` | عملیاتی | `connectionId`، `runId`، `externalRef`، `externalAccountCode`، `amount`، `date`، `raw` (json)، `resolvedAt?` |

- `config` با کلید سازمان در متغیر محیطی رمزنگاری می‌شود (AES-GCM)؛ هیچ‌گاه در پاسخ API یا لاگ نمی‌آید («اطلاعات اتصال رمزنگاری‌شده نگه‌داری می‌شود»، W30).
- نگاشت از `ExternalIdMap(system = erp|accounting)` استفاده می‌کند.

## ۶. قواعد

### ۶.۱ ورود هزینه (ERP و حسابداری)
1. **زمان‌بندی:** ساعتی/شبانه/دستی. نشانگر `cursor` آخرین تغییر.
2. **دریافت** ردیف‌های تعهدی (فاکتور، صورت‌وضعیت پیمانکار جزء، حقوق) از آخرین نشانگر.
3. **نگاشت** با `AccountMapping`؛ نانگاشته ← `UnmappedRow` و ردیفی ساخته نمی‌شود.
4. **ساخت `CostEntry`:** `source = integration`، `externalRef`، `documentNo`، `counterparty`، `costDate` = تاریخ تحقق (قاعدهٔ F06 ۵.۳؛ نه تاریخ پرداخت)، `status`:
   - پیش‌فرض **`draft`**؛ واحد مالی دسته‌ای قطعی می‌کند،
   - با تنظیم `autoPost` اتصال، مستقیم `posted`. `[تأییدشده]`
5. **تغییر در منبع:** سند اصلاح‌شده در بیرون، با همان `externalRef` ولی مبلغ متفاوت: اگر ردیف `posted` است ← ردیف برگشتی + ردیف جدید؛ اگر `draft` است ← به‌روزرسانی.
6. **حذف در منبع:** ردیف برگشتی برای ردیف `posted`؛ حذف برای `draft`.
7. **پایان اجرا:** به‌روزرسانی `costsCompleteThrough` **انجام نمی‌شود** مگر اینکه اتصال این را تنظیم کند و واحد مالی تأیید کرده باشد (مسئولیت انسانی). `[تأییدشده]`
8. **خطا:** `IntegrationRun.status = failed` ← `IntegrationFailed` ← AL-INT-01. تلاش مجدد با تأخیر نمایی؛ پس از ۵ شکست پیاپی اتصال `error` می‌شود (W30: «توکن دسترسی منقضی شده؛ دو همگام‌سازی انجام نشد»).

### ۶.۲ حل ردیف نانگاشته
در W30 (جزئیات خطا) فهرست `UnmappedRow` با پیشنهاد قلم (مشابه عنوان یا کد). با نگاشت، ردیف فوراً ساخته می‌شود و `AccountMapping` برای دفعات بعد می‌ماند.

### ۶.۳ خروجی P6 (فقط خروجی)
- **XER** از نسخهٔ جاری: فعالیت‌ها، تاریخ‌ها، وابستگی‌ها (اگر هست)، درصد پیشرفت تأییدشده، منابع (سرپرست‌ها). دکمهٔ «دریافت XER» (W30). `[تأییدشده]`
- هیچ داده‌ای از P6 به پروژه‌یار برنمی‌گردد.
- خروجی به صورت `GeneratedReport`-مانند (فایل در ذخیره‌سازی، ممیزی دریافت).

### ۶.۴ داده‌های هم‌گام در بوم (W30)
بوم «هزینهٔ واقعی CBS»، «موجودی انبار مصالح» و «حقوق و دستمزد» را می‌گوید. تصمیم:
- **هزینهٔ واقعی CBS** و **حقوق و دستمزد** (به‌صورت ردیف هزینه‌ی نیروی انسانی) ← ورود بخش ۶.۱.
- **موجودی انبار مصالح** ← **نسخهٔ اول و فاز بعد هم نیست**؛ مقدار مصرف‌شدهٔ مصالح از ردیف‌های هزینه با `quantity` می‌آید (`cbs.md` ۸). `[تأییدشده]`

## ۷. اتصال سفارشی
در فاز بعد، Webhook ورودی ساده (`POST /integrations/custom/:token/cost-entries`) با توکن اختصاصی برای شرکت‌هایی که اسکریپت خودشان را دارند. هیچ کد خاص مشتری وارد هسته نمی‌شود. `[تأییدشده]`

## ۸. صفحه (W30، بخش یکپارچه‌سازی)
کارت‌ها: Microsoft Project (F15)، ERP، نرم‌افزار حسابداری، Primavera P6. هر کارت: وضعیت (متصل، آمادهٔ اتصال، خطای اتصال، فقط خروجی)، آخرین همگام‌سازی، عمل (اتصال، همگام‌سازی اکنون، اتصال دوباره، دریافت XER)، «تنظیمات». فرم تنظیمات: نشانی، کلید، داده‌های هم‌گام، «آزمایش و اتصال».

## ۹. محدودهٔ نسخهٔ اول
| شامل | خارج |
|---|---|
| کارت‌های W30 با وضعیت «به‌زودی» برای ERP، حسابداری و P6 | اتصال واقعی |
| API ثبت هزینه (F06) با `source = integration` | نگاشت حساب و `UnmappedRow` |
| جدول `IntegrationConnection` و رابط `IntegrationConnector` (کد) | اجرای زمان‌بندی |
| AL-INT-01 برای MSP | AL-INT-01 برای اتصال‌های دیگر |
| خروجی XML (F15)، Excel جامع، PDF (F18) و XER (اصلاح 1405/08/26) | — |

**رابط `IntegrationConnector`:** `test()`، `pull(cursor)` ← `{rows[], nextCursor}`، `push(payload)`. هر اتصال بعدی فقط یک پیاده‌سازی از این رابط است و در هسته تغییر نمی‌دهد.
