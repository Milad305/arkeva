# Projeyar Dev Servers & Browser Verification

این مهارت جایگزین بومی `.claude/launch.json` و حافظهٔ عملیاتی ورود به پنل در محیط توسعه برای Antigravity است.

## ۱. راه‌اندازی سرورهای محلی (معادل `.claude/launch.json`)

سرورها را با ابزار `run_command` و پارامتر `IsDaemon: true` اجرا کن (هرگز از `curl` یا اسکریپت برای دور زدن رابط مرورگر هنگام تست UI استفاده نکن):

| نام سرویس | پورت | فرمان اجرا | نکتهٔ کلیدی |
|---|---|---|---|
| **API بک‌اند (`projeyar-api`)** | `3000` | `pnpm --filter @projeyar/backend run start` | از روی `dist/main.js` اجرا می‌شود؛ اگر کد `backend/` یا `packages/shared` تغییر کرده ابتدا `pnpm --filter @projeyar/backend run build` بگیر (یا از `start:dev` استفاده کن). در `.env.development` مقدار `APP_ROLE=all` صف `pg-boss` و تیک‌ها را هم بالا می‌آورد. |
| **پنل وب (`projeyar-web`)** | `5173` | `pnpm --dir frontend run dev:dev` | پراکسی Vite مسیر `/v1` را هم‌مبدأ به پورت `3000` می‌فرستد (لازم برای کوکی `HttpOnly` تازه‌سازی نشست). |
| **پنل وب پورت جایگزین** | `5300` | `pnpm --dir frontend exec vite --mode development --port 5300 --strictPort` | زمانی که پورت `5173` اشغال است. |
| **پیش‌نمایش زیرمسیر استقرار** | `5500` | `pnpm --dir frontend exec vite preview --base /panel/ --port 5500 --strictPort` | برای آزمودن `ROUTER_BASENAME` و `appLink` روی زیرمسیر `/panel/` (پیش از اجرا با `VITE_BASE_PATH=/panel/ pnpm --dir frontend run build` ساخته شود). |
| **صفحهٔ فرود (`projeyar-landing`)** | `5400` | `pnpm --dir frontend exec vite ../landing --port 5400 --strictPort` | پیش‌نمایش ایستای پوشهٔ `landing/`. |

> **منع امنیتی مطلق:** هرگز مقادیر کلیدها، رمزها یا رشته‌های اتصال داخل `backend/.env*` را نخوان و در چت چاپ نکن.

## ۲. دستورالعمل ورود در مرورگر (واگذاری به subagent `browser`)

هنگام واگذاری آزمون رابط وب به subagent `browser` (`Model: "flash"` مگر کاربر مدل دیگری بخواهد)، دقیقاً این قواعد را در Prompt او درج کن:

1. به نشانی `http://localhost:5173/login` برو.
2. **برای ورود با مدیر سازمان نمونه (مهندس احمدی)، مقادیر از پیش پرشدهٔ فرم ورود را دست نزن** — فقط دکمهٔ ثبت/ورود فرم را بزن.
3. در صفحهٔ کد تأیید (`/login/otp`)، کد توسعه **`123456`** است. **روی خانهٔ اول کلیک کن و ارقام را یکی‌یکی (یک رقم در هر گام) تایپ کن**؛ تایپ یک‌جای رشتهٔ `"123456"` باعث جا افتادن ارقام در خانه‌های OTP می‌شود.
4. اگر آزمون نیازمند نقش دیگری است، از جدول کاربران نمونهٔ زیر استفاده کن (رمز همه در دادهٔ seed: `Projeyar1404` و کد تأیید وب: `123456`):

| کاربر نمونه | شمارهٔ همراه | نقش شاخص در دادهٔ seed | کاربرد در آزمون |
|---|---|---|---|
| مهندس احمدی | `09123454321` | مدیر سازمان؛ برنامه‌ریز پروژه‌ها؛ مدیر «زیتون» و «مثال مرجع» | دسترسی کامل سازمانی، ویرایش ساختار، ثبت دستی (منع خودتأییدی روی گزارش خودش برقرار است) |
| مهندس رضایی | `09120000201` | مدیر پروژه («نگین»، «پاسارگاد») | تأیید مرحلهٔ دوم، تنظیمات پروژه |
| مهندس کریمی | `09120000202` | ناظر (`reviewer`) در ۱۲ پروژه | تأیید مرحلهٔ اول؛ **فاقد `cbs.view_amounts`** (مناسب تست مخفی شدن مبالغ ریالی) |
| مهندس هاشمی | `09120000203` | واحد مالی در ۱۲ پروژه | مشاهدهٔ مبالغ، دفتر هزینه؛ فاقد ویرایش WBS و تأیید گزارش |
| مهندس نوری | `09120000204` | سرپرست کارگاه در «مثال مرجع» (و مدیر «بیمارستان») | بررسی دامنهٔ محدود سرپرست در پروژهٔ مرجع |
| مهندس توکلی | `09120000209` | ناظر کارفرما در سناریوهای آزمون | تست منفی عدم نمایش مبالغ، شاخص‌های EVM و نمودارها |
| سعید کاظمی (`salehi`) | `09120000210` | فقط سرپرست اپ (وقتی تخصیص بگیرد) | تست خطای `WEB_ACCESS_APP_ONLY` (بسته بودن پنل وب برای کاربر صرفاً اپ) |
| علی همتی (`hamidi`) | `09120000211` | بدون پروژه | تست قفل شدن حساب پس از تلاش ناموفق |

## ۳. منابع تکمیلی عیب‌یابی آزمون دستی
- برای سناریوهای پیوستهٔ `S01` تا `S29` و فهرست ده ایراد احتمالی شناخته‌شده، فایل [`docs/manual-test-guide.md`](../../../docs/manual-test-guide.md) (به‌ویژه بخش‌های ۰، ۷ و ۸) را بخوان.
- اگر پس از تأیید گزارش عدد پیشرفت یا EVM بلافاصله تغییر نکرد، نشانگر «در حال به‌روزرسانی» را چک کن (محاسبه در صف `pg-boss` اجرا می‌شود و نیازمند بالا بودن کارگر با `APP_ROLE=all` است).
